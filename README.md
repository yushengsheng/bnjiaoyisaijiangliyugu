# EventLens Local

本地运行的币安交易赛排行榜、奖励和买卖价差分析工具。页面风格参考 EventLens，但所有活动配置、排行榜快照和历史记录均保存在当前电脑，不需要浏览器扩展，也不会开放局域网或公网服务。

正式版下载：[EventLens Local v2.1.2](https://github.com/yushengsheng/bnjiaoyisaijiangliyugu/releases/tag/v2.1.2)。下载 `EventLens-Local-v2.1.2.zip` 后解压，仍需安装 Node.js 22+；`SHA256SUMS` 用于核对下载文件。

## 功能

- 从币安公告链接、公告代码或交易赛页面录入活动；多赛道交易者联赛必须粘贴具体 Round/子赛道排行榜链接。
- 使用本机 Brave/Chrome 读取公开排行榜，并抓取**全部分页**后再计算。
- 统计全部参与人数、总交易量、前 N 名交易量、后段交易量和奖励档位门槛。
- 后段奖励按“新增榜单计入量加入当前后段分母”估算，并应用公告中的单人奖励上限。
- 获取币安公开买一/卖一，优先使用单次批量请求，按“手续费 + 简单买卖价差”估算每千 U、每万 U 榜单计入量成本；活动有 1.2x 等倍数时会折算所需实际成交量。
- 行情不可用时明确显示不可用，不会生成假价格、假盘口或假排行榜。
- 保存最近 500 次成功快照，用于本地趋势和 CSV 导出。
- 可勾选开启或关闭每 30 分钟排行榜自动更新；关闭后保留手动更新，选择会保存到本机并在下次启动时恢复。
- 自动区分源数据时间、本地采集时间和最近检查时间。

> 排行榜自身的更新频率由币安决定。程序每 30 分钟检查一次，不代表币安排行榜每 30 分钟变化。
>
> 交易者联赛等包含多个独立赛道的综合公告不能仅凭公告代码安全确定目标榜单。请直接粘贴用户实际选择的具体 Round/子赛道 URL，工具会拒绝猜测。

## 系统要求

- Node.js 22 或更高版本
- Brave Browser 或 Google Chrome
- macOS、Windows 或常见 Linux 桌面系统

项目不依赖第三方 npm 包，无需运行 `npm install`。

## 启动

### macOS

双击应用（请保留在项目文件夹中）：

```text
双击打开.app
```

项目可保留在下载、桌面、文稿或其他有读写权限的文件夹中，支持中文、空格和特殊字符路径。原生启动器支持 Apple Silicon 和 Intel Mac；首次访问 macOS 保护的目录时，请在系统提示中选择“允许”。若此前拒绝了权限，启动器会打开文件夹选择窗口，选择当前项目文件夹并点击“允许访问”即可，无需授予完全磁盘访问权限。

后台运行，不需要保留终端窗口。关闭最后一个 EventLens 网页约 10 秒后，服务自动退出；刷新页面或保留其他活动标签页不会退出。若浏览器未打开，服务在约 90 秒后退出。退出后再次双击应用即可启动，监控与快照仍保存在本地。

启动器会检查本项目的运行版本，代码更新后自动替换旧服务。网页、脚本和样式不再缓存，资源地址也带版本，避免浏览器继续显示旧界面。

旧的 `.command` 文件保留兼容入口，但 macOS 仍会为它们短暂打开终端；日常请使用 `.app`。首次从旧版本升级，若原有终端服务占用端口，请先关闭该终端窗口。

应用使用 ad-hoc 本地签名，未经过 Apple 开发者签名或公证。如果首次运行被 macOS 拦截，请右键应用并选择“打开”。也可以在终端运行（此模式保持运行，不随页面关闭）：

```bash
./start.sh
```

开发时修改原生启动器源码 `scripts/macos-launcher.m` 后，在 macOS 上运行 `bash scripts/build-macos-launcher.sh` 重新生成应用。发布包已包含编译好的通用启动器，使用者无需安装编译工具。

## 排行榜准确性

采集流程：

1. 打开指定活动的主奖池页面。
2. 只接受当前页面实际请求过的 Resource ID。
3. 获取排行榜全部分页。
4. 按公开参与者标识去重，校验首名为 1、展示排名单调不降且交易量单调不升；允许币安真实存在的并列名次。
5. 校验实际记录数与官方分页总数；抓取期间人数变化时从第 1 页完整重试一次。
6. 使用微美元整数单位累计交易量，并与官方聚合总量核对；只允许一美分或逐行微单位精度范围内的微小差异。
7. 完整性校验通过后才覆盖最新快照。

任何分页缺失、参与者重复或人数不一致都会判定为失败，并保留上一次成功快照。

## 成本模型

上榜记录直接视为满足活动资格，不在本地重复校验 500 U 最低交易量。后段奖励卡片模拟从零新增一名参与者，且假设其他人的交易量不变；模拟量达到当前排名奖励门槛时，提示查看排名明细，不再套用后段公式或显示后段净收益。均分奖池按新增一人计算，比例奖池按新增交易量计算；无上限与零上限分别处理。

下方“前 1,000 名排名明细”始终以紧凑小卡片显示奖励档汇总，保留该档末名交易量、每名奖励、末名估算成本及利润；下方逐名明细可独立展开、收起。展开后展示每个名次的榜单交易量、估算成本、对应奖励及估算利润。输入整数名次可直接搜索；每页显示 50 条，点击单条排名可查看实际成交量折算、手续费、价差成本及利润计算。成本默认取当前可用参赛币对中最低的一项，也可切换币对，使用上方费率和返佣设置；奖励按各自币种的当前价格估值。该估算不代表参赛者实际盈亏，不包含独立分轮奖励。跨奖励边界的并列名次保留交易量，奖励和利润标为待核对。

旧快照只保存汇总，需点击“获取逐名排行榜”更新一次才能查看完整明细；不会根据门槛插值或补造交易量。新快照保存前 1,000 条逐名数据，趋势历史仍仅保存汇总。完整分析 CSV 同时包含逐名估算结果。

缺失的门槛和行情显示为未知。不同奖励币分别取价；未识别的分配方式、多主奖池歧义和排名边界并列会暂停收益估算，保留快照与规则供核对。

按用户设定，成本模型保持简单：

- 成交手续费：`交易量 × 基础费率 × (1 - 返佣比例)`
- 买卖价差：使用当前买一和卖一简单估算
- 不模拟多档订单簿和大额订单冲击

因此页面使用“买卖价差成本估算”，不宣称是真实深度滑点。奖励与币对成本统一使用“榜单计入量”口径；顶部基础手续费则明确标为“实际成交量”口径。

基础费率需填写 0 到 0.02 之间的小数，返佣比例需填写 0 到 1 之间的小数；空值或越界输入会暂停成本和利润估算，修正后自动恢复。行情刷新失败时同样停止使用旧盘口计算，保留排行榜交易量和奖励信息供查看。

## 安全设计

- 仅允许回环地址访问。
- 所有添加、删除、写快照和触发爬虫操作都需要当前页面的随机本地会话令牌。
- 拒绝跨站写操作。
- 支持 HTTPS 公网域名下的交易赛活动链接，包括新镜像和自定义域名；保留输入域名，失败时按原活动路径尝试备用主机。
- 拒绝本机、内网、IP 地址、带登录信息和异常端口的活动链接；启动抓榜前校验域名解析结果。规则仍从币安公告按活动 ID 匹配，未知规则标为待核对。
- 静态文件访问被限制在 `public/` 目录内。
- 不读取币安账户、API Key、钱包、登录凭据或私人交易记录。
